# План notebook `03_central_fusion_model_raw_data.ipynb`

## Глобальный контекст

Этот план продолжает пересборку цепочки notebook на правильном датасете `raw_data/`:

1. `01_eda_raw_data.ipynb` выявил структуру данных, ограничения provenance, временные масштабы и риски coverage shortcut.
2. `02_multirate_baseline_raw_data.ipynb` собрал воспроизводимый multi-rate contract и smoke baselines.
3. Новый `03_central_fusion_model_raw_data.ipynb` должен подготовить и описать **полное обучение центральной мультимодальной модели** поверх нового contract, но в обычной проверке notebook не должен запускать тяжёлый training loop.

Источник методической логики: `lcman/notebooks_rebuild_map.md`, раздел `Notebook 03_lightweight_multimodal_system.ipynb`: log macro branch, log micro branch, KPI 1D-CNN, gated missing-aware fusion, dual heads, modality dropout, repeated group-aware evaluation, model card и inference store.

Старые численные результаты и legacy fallback не переносить. Старый `lcman/old_broke_data_pype/03_lightweight_multimodal_system.ipynb` можно использовать только как архитектурную подсказку, но не как источник данных, метрик или путей.

## Главная цель

Создать notebook `03_central_fusion_model_raw_data.ipynb` в корне проекта.

Notebook должен:

- строго загрузить `outputs/raw_multirate/aligned_multirate_windows.csv` и `outputs/raw_multirate/feature_schema.json`;
- не иметь silent fallback на legacy artifacts;
- подготовить multi-rate inputs для центральной модели:
  - `log_embedding` из `log_text`;
  - `log_macro` numeric context;
  - `log_micro` numeric dynamics;
  - `kpi_tensor` из series-aware KPI columns;
  - `kpi_micro`/coverage numeric vector;
  - modality masks;
- описать центральную gated-fusion архитектуру:
  - Log macro branch;
  - Log micro branch;
  - KPI branch через 1D-CNN или документированный fallback;
  - gated missing-aware fusion;
  - dual heads для `y_warning` и `y_risk`;
- реализовать полный train/validation/test protocol с early stopping, но **по умолчанию не запускать полный training loop**;
- выполнить dry-run проверку: preprocessing, tensorization, model construction, one mini-batch forward pass, loss computation, optional single backward pass;
- при включении full training через явный флаг обучить центральную модель и сравнить её с baseline controls из `02`;
- выполнить coverage-aware evaluation, modality ablation и gate analysis для обученного checkpoint;
- сохранить manifests, dry-run report, а training artifacts сохранять только если full training включён.

## Режимы выполнения

Notebook должен иметь явный переключатель:

```python
RUN_FULL_TRAINING = False
```

Default mode для локальной проверки:

- выполняется весь data loading и preprocessing;
- строятся feature groups, embeddings, KPI tensor, masks;
- создаются train/validation/test splits;
- инстанцируется модель;
- выполняется один mini-batch forward pass;
- считается loss;
- желательно выполняется один `loss.backward()` без epoch loop, чтобы проверить вычислительный граф;
- сохраняются dry-run manifests и reports;
- полный training loop, repeated evaluation, checkpoint selection, ablation over trained model и финальная inference scoring **не запускаются**.

Full training mode для запуска на машине с графическим ускорителем:

```python
RUN_FULL_TRAINING = True
```

В этом режиме запускаются:

- полный training loop с early stopping;
- threshold selection on validation;
- evaluation on test;
- comparison with `02` baselines;
- modality ablation;
- gate analysis;
- interpretability cases;
- checkpoint and inference store saving.

Notebook должен явно печатать текущий режим и завершаться без ошибок в default dry-run mode.

## Непереговорные ограничения

- Не читать старые `log_csv/`, `kpi_csv/`, `outputs/final_demo/`.
- Не делать fallback на старый `scored_windows_reference.csv`.
- Не использовать `workload`, `scenario`, `run_id`, `group_id`, `failure_family`, `scenario_type`, `state`, `anchor_policy`, timestamps, path-like columns и target columns как predictive features.
- Не подбирать threshold, scaler, vectorizer, SVD, imputer, KPI normalization или early stopping по test split.
- Не обучать text encoder на all data, если он fit-based (`TfidfVectorizer`, `TruncatedSVD`): fit только на train/inner-train.
- Не использовать HF token checks, не выводить secrets, не требовать сетевой download для embeddings.
- Не утверждать, что `run_end_proxy` является истинным fault timestamp.
- Не трактовать `availability-only` как финальную модель; это shortcut control.
- Не форсировать вывод, что центральная модель обязана превзойти fused baseline. Если не превосходит, честно объяснить через target proxy, coverage, small data и split variance.
- Не превращать `03` в model zoo: центральная модель одна, baselines только для сравнения.
- В default execution mode не запускать полный training loop. Проверка notebook должна быть быстрой и ограниченной dry-run режимом.

### 5. KPI tensorization

### 7. Architecture card before training

Notebook должен показать таблицу блоков:

| Block | Input | Output | Purpose |
|---|---|---|---|
| Log macro | `[log_embedding, log_macro]` | `h_macro` | semantic + 60s context |
| Log micro | `log_micro` | `h_micro` | 10s dynamics |
| Log fuse | `[h_macro, h_micro]` | `h_log` | log modality representation |
| KPI branch | `kpi_tensor + kpi_micro` | `h_kpi` | series-aware KPI dynamics |
| Gate | `[h_log, h_kpi, masks]` | scalar `g` | missing-aware late fusion |
| Dual heads | `h_fused` | warning/risk logits | primary + secondary targets |

Recommended architecture:

```text
DenseBlock(input -> 128 -> hidden_dim)
LogMacroBranch: DenseBlock(emb_dim + log_macro_dim, hidden_dim=64)
LogMicroBranch: DenseBlock(log_micro_dim, hidden_dim=64)
LogFuse: Linear(128 -> 64)
KPIBranch1DCNN: Conv1d(C -> 32) -> Conv1d(32 -> 32) -> AdaptiveMaxPool1d + KPI micro MLP -> 64
Gate: sigmoid(Linear([h_log, h_kpi, log_mask, kpi_mask, kpi_ratio] -> 1))
Fallback rules: no KPI -> gate=1, no log -> gate=0, none -> gate=0.5
Heads: warning_head, risk_head
Aux heads optional: log_only_warning, kpi_only_warning, fused_aux_warning
```

Default hyperparameters for full training mode:

```text
hidden_dim = 64
batch_size = 128 or 256
max_epochs = 120
patience = 12-16
lr = 1e-3
weight_decay = 1e-4
modality_dropout = 0.20
lambda_risk = 0.35
lambda_aux = 0.10
seed = 42
```

Default dry-run mode must instantiate exactly the same architecture/config but run only a tiny compatibility check.

### 9. Full training loop, gated by flag

Этот блок должен быть реализован, но выполняться только если:

```python
if RUN_FULL_TRAINING:
    ...
```

Содержание:

- set deterministic seeds;
- create full PyTorch `Dataset` and `DataLoader`;
- normalize numeric arrays using train/inner-train only;
- compute `pos_weight_warning` and `pos_weight_risk` from train only;
- loss:

```text
loss = BCE_warning + lambda_risk * BCE_risk + lambda_aux * aux_warning_loss
```

- early stopping by validation PR-AUC for `y_warning`;
- store history: epoch, train_loss, val_loss, val_pr_warning, val_pr_risk, learning rate if used;
- save best state dict;
- support graceful skip if validation target degenerates, but contract from `02` suggests it should not.

Train balancing options:

- default: BCE pos_weight + shuffled batches;
- optional: `WeightedRandomSampler` by `y_warning` if model collapses to majority class;
- optional hard-negative oversampling, but only from train split.

### 10. Evaluation and comparison with `02` baselines

В default dry-run mode этот блок должен быть skipped с понятным markdown/report: metrics unavailable because full training was not run.

В full training mode считать:

Metrics:

- primary: Average Precision / PR-AUC for `y_warning`;
- secondary: PR-AUC for `y_risk`;
- ROC-AUC only when both classes present;
- precision, recall, F1 at threshold 0.5 and val-selected threshold;
- prevalence baseline for context.

Slices:

- all test windows;
- `kpi_available = 1`;
- `has_both_modalities = 1`;
- `anchor_policy = explicit_raw_log_keyword_or_severity`;
- `anchor_policy = run_end_proxy`;
- normal/failure/family slices if each slice has enough rows and positives;
- optional workload slices for diagnostic only, not primary conclusion.

Comparison:

- load `baseline_summary_metrics.json` from `02`;
- build `baseline_comparison.csv` with rows for `availability-only`, `log-only`, `kpi-only`, `fused`, `central-fusion-model`;
- primary comparison is central model vs `fused` and `availability-only` for `y_warning` all test windows;
- also compare on `has_both_modalities=1`, because fusion should matter there.

Important interpretation:
